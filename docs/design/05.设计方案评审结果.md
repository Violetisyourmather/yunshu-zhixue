### 2.2 核心链路覆盖

- 学：路线 → 课程 → 标记完成 → 已学课程（`route_course_completion` + A-U06/P-M01）
- 练：题库 → 练习 → 判分 → 作答记录 → 错题（`practice_record` / `wrong_question` / P-P02）
- 测：配置 → 题库抽题 → 逐题评分 → 报告（`interview_*` / P-I01~I05）
- 管：学科/课程/题库审核/路线/学员/权限/日志/设置（A-* 全套）
- 统计：累计学习天数、正确率、掌握率、看板指标均由明细聚合，无冗余统计表

**未发现核心需求缺表或缺接口。** 以下两项为「已确认的裁剪」，不属于缺失：课程播放量（D4-7 移除）、首页好评率（T13 移除）。

## 3. 架构合理性检查

| 检查项 | 结论 |
|---|---|
| 技术栈一致性 | Java 17 / Spring Boot 3 / MySQL 8 / Redis 7 / Vue 3 / Element Plus / ECharts 在 02/03/04 中一致，无擅自更换 |
| 模块边界 | 12 个领域模块，单向依赖；`ai` 无状态、`stats` 只读、`security` 为底座；04 的接口分组与 02 §3.1 映射一致 |
| 服务边界 | 模块化单体，不跨模块直连数据库；04 未出现跨模块访问他表的情况 |
| 实时链路 | SSE 仅用于刷题简答与面试逐题评分，与 02 D19 一致；04 P-P02/P-I03 均为 `text/event-stream` |
| 会话与持久化 | 未完成面试不落业务库（前端本地 + Redis 暂存），结束时单事务落库；02 D16、03 §3.7、04 P-I04 三处一致 |
| 缓存与配额 | 配额、验证码、登录态、看板缓存均在 Redis，键设计见 04 §2.12，与 02 §2.5 一致 |
| 部署形态 | 同域分区 `/`、`/admin`、`/api`；双端 JWT 隔离，无跨端共享 token |

结论：架构合理，无明显过度设计；唯一需要关注的是「模块化单体 + 多模块共享库表」在长期演进中的边界侵蚀，已列 R9 风险。
