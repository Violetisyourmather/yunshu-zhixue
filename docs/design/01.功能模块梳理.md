## 1. 项目定位与角色

### 1.1 定位与形态

**定位**：AI 赋能的智能面试训练平台，以「学路线 → 刷题 → AI 面试 → 看报告补强」为核心训练闭环。

**形态**：

| 端 | 说明 | 入口 |
|---|---|---|
| 学员端（Portal） | 独立部署、独立账号体系，面向学员与游客 | 身份选择页 → 学生端 |
| 管理端（Admin） | 独立部署、独立账号体系，面向运营/审核/管理员 | 身份选择页 → 管理端 |

两端的入口在原型中收敛为一个身份选择页（`#/`）；该页属于演示入口，不是需求文档中的业务页面。

### 1.2 角色与权限边界

| 角色 | 所属端 | 权限范围（依据需求文档 1.2 与旧版结论） |
|---|---|---|
| 游客 | 学员端 | 浏览首页、注册、登录、找回密码 |
| 学员 | 学员端 | 学习路线、题库与练习、错题本、AI 面试、个人中心 |
| 超级管理员 | 管理端 | 全部权限 |
| 内容审核 | 管理端 | 查看全部内容 + 题库审核；无新增、编辑、删除、导入导出 |
| 运营人员 | 管理端 | 除系统管理外的全部操作；不含题库审核 |

> 权限树按旧版为 **9 组**：题库管理、面试题库管理、用户管理、学习路线、学员管理、系统管理、数据看板、学科管理、B站课程库。
> 角色管理未单列权限组，仅超级管理员可访问。

### 1.3 核心闭环

```
学习路线（学科 → 有序课程 → B 站 → 手动勾选完成）
        ↓
      刷题练习（按阶段，即时判分）
        ↓
      错题本（连对 3 次转为已掌握）
        ↓
      AI 面试（方向/难度/题数 → 逐题评分 → 报告）
        ↓
      报告补强（推荐题目 / 推荐课程 / 再次面试）
        └────────────→ 回到题库与路线
```

## 3. 功能模块划分与职责

### 3.1 划分原则

1. 按**业务职责**划分，不按页面 1:1 映射。
2. **生产与消费分离**：管理端负责内容生产与审核，学员端只消费已上架内容。
3. **横切能力单列**：认证鉴权、频控、AI 能力、统计口径不归属任何单一页面。
4. 每个模块写清「做什么」与「不做什么」，避免职责重叠。

### 3.2 模块总览

| 编号 | 端 | 模块 | 子模块 | 主要视图 |
|---|---|---|---|---|
| P1 | 学员端 | 账号与门户 | 注册 / 登录 / 找回密码 / 首页 | `#/login` `#/register` `#/forgot` `#/home` |
| P2 | 学员端 | 学习训练 | 题库中心 / 刷题练习 / 错题本 / 学习路线 | `#/bank` `#/practice` `#/wrong` `#/routes` |
| P3 | 学员端 | AI 面试 | 配置 / 进行中 / 报告 / 记录 | `#/interview` 等 4 个视图 |
| P4 | 学员端 | 个人中心 | 资料维护 / 学习数据 | `#/profile` |
| A1 | 管理端 | 数据概览 | 数据看板 | `#/admin/dashboard` |
| A2 | 管理端 | 内容管理 | 学科与阶段 / 课程库 / 题库 / 面试题库 / 学习路线 | `#/admin/subjects` 等 5 个 |
| A3 | 管理端 | 学员管理 | 学员列表 / 详情 / 启禁用 / 导出 | `#/admin/students` |
| A4 | 管理端 | 系统管理 | 用户 / 角色 / 操作日志 / 系统设置 | `#/admin/users` 等 4 个 |
| S1 | 支撑 | 认证与权限 | 双端登录态 / RBAC / 菜单与按钮可见性 | 横切 |
| S2 | 支撑 | 安全与频控 | 登录锁定 / 验证码频控 / 接口频控 | 横切 |
| S3 | 支撑 | AI 能力 | 简答批改 / 面试出题 / 逐题评分 / 报告汇总 / 语音 | 横切 |
| S4 | 支撑 | 记录与统计 | 作答记录 / 已学课程 / 面试记录 / 统计口径 | 横切 |

### 3.3 各模块职责

**P1 账号与门户**

- 职责：账号生命周期（注册、登录、找回密码）、游客与学员身份切换、首页内容聚合与入口分发。
- 关键功能：注册与登录校验、验证码倒计时、密码强度、登录态保持、首页统计与快捷入口、新手引导。
- 边界：不产生内容；不负责权限树（归 S1）；首页只做展示与跳转。
- 依赖：S2、S4、P2/P3。

**P2 学习训练**

- 职责：题库浏览与筛选、练习会话、客观题判定、简答 AI 批改、错题归集与掌握判定、学习路线展示、B 站跳转、课程完成勾选。
- 关键功能：按学科/阶段浏览、题型难度筛选、顺序/随机（可选题量）练习、答题卡、计时、断点续做、错题重做、已学课程勾选。
- 边界：不生产内容；不做面试评分；课程完成由学员手动勾选，平台不采集观看行为。
- 依赖：A2、S3、S4。

**P3 AI 面试**

- 职责：面试配置、按方向（=学科）取题组卷、对话式作答、逐题评分、报告生成、历史记录。
- 关键功能：方向/难度/题数选择、配额校验、单题 5 分钟、语音播报与语音转文字、报告与补强建议。
- 边界：不维护面试题（归 A2）；不提供下载/分享；报告不直接修改学习数据。
- 依赖：A2、S3、S4。

**P4 个人中心**

- 职责：学员本人资料维护与学习数据展示。
- 边界：不含注销与换绑手机号（需求未定义）；不展示运营视角数据。
- 依赖：S4。

**A1 数据概览**

- 职责：平台核心指标、趋势、分布与最近活动的聚合展示。
- 边界：只读；不下钻明细；指标口径由 S4 定义。
- 依赖：S4、A2/A3。

**A2 内容管理**

- 职责：学科与阶段、B 站课程库、题库（含审核）、面试题库、学习路线的生产与维护，是学员端内容的唯一来源。
- 子模块分工：
  - 学科与阶段：内容树第一层与题目挂载层级。
  - 课程库：独立维护，bvid 唯一，可关联多个学科，可被多条路线引用。
  - 题库：CRUD、审核状态机、导入导出、批量上下架。
  - 面试题库：按方向（=学科）归属，维护主题与难度，支持录入与 Markdown 导入。
  - 学习路线：单学科归属，编排有序课程，可跨学科补充。
- 边界：不管理学员；不产生作答数据；审核与编辑权限分离。
- 依赖：S1、A4。

**A3 学员管理**

- 职责：学员列表、详情、启用/禁用、批量操作、导出。
- 边界：学员由前台注册产生，后台不新增/编辑学员。
- 依赖：S4、S1。

**A4 系统管理**

- 职责：后台账号、角色与权限树、操作日志、平台基本信息。
- 边界：不涉及学员账号；系统设置仅基本信息。
- 依赖：S1。

**S1 认证与权限**

- 职责：两端独立登录态；管理端按权限点控制菜单与按钮可见性。
- 边界：不做业务判断；角色默认权限以旧版 9 组为准。

**S2 安全与频控**

- 职责：登录失败锁定、验证码获取与校验限制、关键接口按 IP＋账号频控。
- 边界：阈值固定，不在前端暴露。

**S3 AI 能力**

- 职责：简答批改、面试出题、逐题评分、报告汇总、语音识别与播报。
- 边界：不存储内容；评分结果由 P2/P3 落库展示。

**S4 记录与统计**

- 职责：维护作答记录、面试提交记录、课程完成记录，向首页、个人中心、看板、学员详情提供统一口径。
- 边界：没有独立页面；不做展示层设计。
- 口径：学习天数为累计口径（有作答记录的累计自然日数）；首页连续学习天数单独计算。

### 3.4 模块边界澄清

| 易混淆的两者 | 区别 |
|---|---|
| 题库中心（P2） vs 题库管理（A2） | 前者消费已上架题目并产生作答；后者生产、审核、上下架 |
| 刷题练习（P2） vs 错题本（P2） | 练习负责判定与归集；错题本负责复习、重做与掌握状态 |
| 学习路线（P2） vs 学习路线管理（A2） | 前者展示、跳转与勾选完成；后者编排、排序、启停 |
| AI 面试（P3） vs 面试题库管理（A2） | 前者组卷、作答、评分、报告；后者提供题目与主题/难度 |
| 个人中心（P4） vs 学员管理（A3） | 本人视角 vs 运营视角；后者不能编辑学员资料 |
| 首页统计（P1） vs 数据看板（A1） | 学员个人口径 vs 平台汇总口径，共用 S4 |

## 4. 模块关系与核心业务流程

### 4.1 内容与对象关系

```
学科（8）
 ├─ 1:N ─ 阶段 ─ 1:N ─ 题目（已上架后供题库中心 / 刷题 / 错题消费）
 ├─ N:M ─ B站课程（课程库；bvid 唯一；可关联多学科；上架/下架）
 │          └─ N:M ─ 学习路线（有序引用；可额外添加其他学科课程）
 └─ 1:N ─ 面试题（方向 = 学科，按方向归属）

学习路线 ─ 学员勾选「已完成」──→ 已学课程（计入学员详情与统计）
```

要点：

- 课程与学科：**多对多**，一门课可属多个学科（旧版确认）。
- 课程与路线：一门课程可被多条路线引用；路线内课程有序。
- 路线归属：单学科路线；课程选择器保留「其他学科课程（跨学科补充）」。
- 面试方向：**直接复用 8 个学科**，不另设方向体系与映射表。
- 面试题库：无独立「知识库」实体，题目按方向（=学科）归属，来源记录文档名文本。

### 4.2 模块依赖

| 消费方 | 依赖内容 | 提供方 |
|---|---|---|
| P1 首页 | 学习统计、平台数据、学科与阶段 | S4、A2 |
| P2 学习训练 | 已上架题目、课程、路线、简答批改、记录 | A2、S3、S4 |
| P3 AI 面试 | 面试题（按方向）、评分与汇总、面试记录 | A2、S3、S4 |
| P4 个人中心 | 学习统计 | S4 |
| A1 看板 | 平台汇总统计 | S4 |
| A2 内容管理 | 权限点、角色 | S1、A4 |
| A3 学员管理 | 学习统计、权限点 | S4、S1 |
| A4 系统管理 | 权限点 | S1 |
| 全部管理端模块 | 登录态、鉴权、日志写入 | S1、S2、A4 |

强依赖关系：

- **A2 是 P2/P3 的唯一内容来源**：题目上架/下架、路线启停、面试题修改会即时影响学员端。
- **S3 是简答批改与面试评分的共同能力**：共用「要点命中」逻辑。
- **S4 是跨端统计的唯一口径来源**。

### 4.3 核心业务流程

**流程一：内容生产与上架（管理端）**

```
学科 / 阶段（A2）→ 课程库录入课程（多学科、bvid、简介、上下架）
      → 学习路线：选学科 + 勾选课程 + 排序 → 启用（A2）
题目：新增 / 导入 → 待审核 → 审核通过（已上架）或驳回（已驳回）
      → 已上架 → 下架（已下架）→ 重新上架需回到待审核
面试题：录入 / Markdown 导入 → 指定方向（=学科）、主题、难度 → 上架
```

**流程二：学习路径（学员端）**

```
首页 / 学习路线 → 选择学科 → 查看路线与课程顺序
      → 点击「去B站学习」→ 新标签打开 B 站
      → 回到平台手动勾选该课程「已完成」→ 计入已学课程
```

**流程三：刷题与错题闭环（学员端）**

```
题库中心：学科 → 阶段 → 题目（题型/难度/关键词筛选）
      → 开始练习：顺序 / 随机（可指定题量）
      → 作答：客观题即时判分；简答题提交后 AI 批改（≥6 通过）
      → 展示结果与解析 → 下一题 / 结束练习（二次确认）
      → 答错自动进错题本（错误次数 +1、按次数分级）
      → 错题重做：连续答对 3 次 → 已掌握
```

**流程四：AI 面试闭环（学员端）**

```
配置：方向（=学科）+ 难度 + 题数（默认 10）→ 校验今日剩余次数（5 次/天）
      → 取该学科面试题组卷
      → 逐题作答（文字 / 实时语音转文字；单题限时 5 分钟）
      → 每题 0–10 分 + 要点命中 + 简短点评
      → 全部答完 / 手动结束 → 生成报告
      → 报告：综合评分 + 能力分析 + 优缺点 + 改进建议 + 三张提升卡
      → 面试记录留存，可查看报告 / 再来一次 / 查看回放
```

**流程五：运营与审计（管理端）**

```
看板监控（A1）→ 学员管理（A3：详情 / 禁用 / 导出）
      → 系统管理（A4：用户 / 角色 / 权限 / 设置）
      → 全部写操作与登录行为进入操作日志
```

### 4.4 关键状态

| 对象 | 状态 | 说明 |
|---|---|---|
| 题目 | 待审核 → 已上架 / 已驳回；已上架 → 已下架 → 重新上架回待审核 | 草稿为预留值，当前不启用 |
| 课程 | 上架 / 下架 | 下架后学员端不可见 |
| 学习路线 | 启用 / 禁用 | 禁用后学员端是否展示待确认（L6） |
| 学员 | 已启用 / 已禁用 | 逻辑删除 |
| 后台用户 | 已启用 / 已禁用 | 超级管理员为内置唯一账号 |
| 练习会话 | 进行中 → 已完成 / 中途退出；未完成可续做 | 进度存本地 |
| 面试会话 | 进行中 → 已完成 / 主动结束 → 生成报告 | 报告归属当次记录 |
| 错题 | 待复习 / 已掌握 | 连续答对 3 次自动转已掌握 |
| 课程完成 | 未完成 / 已完成（学员勾选） | 勾选后计入已学课程 |

### 4.5 权限如何贯穿

- 管理端菜单与操作按钮由权限点控制；无权限入口不展示。
- 预置三角色：超级管理员全量；内容审核只读＋审核；运营除系统管理外全量且无审核。
- 全部写操作、审核、上下架、启禁用进入操作日志。
- 学员端不做细粒度权限，只区分游客与已登录学员。
